2. COMMENT LA PAGE EST UTILISEE
-------------------------------
Le meme fichier sert trois usages, selon l'adresse ouverte :
l'adresse nue pour voter, ?resultat pour projeter, ?demo pour
repeter.

LES TELEPHONES ouvrent l'adresse nue, celle du QR code :
    https://votre-compte.github.io/sondage-mondelez/
Ils voient les trois questions, votent, recoivent un remerciement.
Ils ne voient jamais les resultats : aucun bouton ne leur est
propose.

L'ECRAN DE PROJECTION ouvre la meme adresse suivie de ?resultat :
    https://votre-compte.github.io/sondage-mondelez/?resultat
Pas de formulaire, pas de bouton : les resultats sont affiches des
l'ouverture et se remplissent tout seuls. A chaque vote qui arrive,
la creme des biscuits monte ou descend vers le nouveau pourcentage.
Tout y est agrandi pour rester lisible du fond de la salle. Ouvrez
cet onglet avant de projeter le QR code, et laissez-le tourner.

N'oubliez pas le ?resultat sur l'ordinateur : sans lui, vous
obtiendrez le formulaire, pas les resultats.

POUR REPETER AVANT L'ORAL : ouvrez l'adresse suivie de ?demo
    https://votre-compte.github.io/sondage-mondelez/?demo
Vous obtenez l'ecran de projection rempli de douze votes inventes,
avec un bandeau rouge qui le dit. Rien n'est envoye ni lu nulle
part. Cela marche meme si le service de collecte n'existe pas
encore : c'est fait pour repeter l'enchainement, verifier la
lisibilite au videoprojecteur et montrer le rendu au groupe.

SI VOUS PREFEREZ GARDER LE SUSPENSE : dans index.html, cherchez la
ligne   var REVELATION = "direct";   et remplacez direct par bouton.
L'ecran attendra alors un clic sur « Voir le resultat du sondage »
pour tout devoiler d'un coup. A vous de voir : en direct, la salle
voit les reponses pendant qu'elle vote, ce qui influence les
derniers votants ; avec le bouton, l'effet de devoilement est plus
fort mais il faut penser a cliquer.


3. LA COLLECTE DES VOTES : RIEN A FAIRE
---------------------------------------
Il n'y a aucun compte a creer, aucune cle a coller, aucune base de
donnees a configurer. La page est prete a servir telle quelle.

Comment ca marche : chaque reponse possible a son compteur chez
Abacus, un service de compteurs publics et gratuits. Un vote fait
monter d'une unite le compteur de chaque reponse choisie, plus un
compteur « votants » qui sert a calculer les pourcentages. L'ecran
relit ces compteurs toutes les cinq secondes et remplit les
biscuits. Personne ne s'inscrit nulle part.

Vos compteurs sont ranges sous un nom tire au hasard, visible en
haut du script :

      var ESPACE = "mondelez-icn-g1-..."

POUR REPARTIR DE ZERO apres les essais : changez ce nom. Mettez-en
un autre, aussi long et aussi peu devinable, par exemple en
changeant quelques lettres a la fin. Des compteurs neufs partent
tous a zero. C'est la seule facon d'effacer : on ne remet pas un
compteur en arriere.

CE QU'IL FAUT SAVOIR, HONNETEMENT :
- Ce nom se trouve dans le code de la page, que n'importe qui peut
  lire. Quelqu'un de determine pourrait donc faire monter vos
  compteurs. Pour un sondage de cours, le risque est theorique,
  mais ne publiez pas ce nom ailleurs que dans la page.
- Abacus est un service gratuit, sans engagement. S'il est lent ou
  indisponible le jour J, l'ecran affiche « Resultats momentanement
  indisponibles » et reessaie tout seul. Si cela dure, basculez sur
  Wooclap (section 11).
- Le site a ete teste de bout en bout contre ce service : deux
  telephones ont vote, l'ecran a suivi, les pourcentages etaient
  justes et le second vote depuis le meme appareil a bien ete
  refuse.


4. METTRE LA PAGE EN LIGNE (GITHUB PAGES)
-----------------------------------------
a) Sur github.com : « New repository ». Nom au choix, par exemple
   sondage-mondelez. Cocher « Public ». Creer.
b) « uploading an existing file », deposer index.html.
   Important : le fichier doit s'appeler index.html et se trouver
   a la racine du depot, pas dans un sous-dossier.
c) Onglet Settings > Pages.
   - Source : « Deploy from a branch »
   - Branch : main   -   dossier : / (root)   -   Save
d) Attendre une a deux minutes, puis recharger Settings > Pages :
   l'adresse publique s'affiche en haut.
e) L'ouvrir sur un telephone pour verifier.

Pour modifier la page plus tard, redeposer le fichier au meme
endroit : GitHub remplace l'ancien et publie en une minute.


5. LE QR CODE
-------------
Une fois l'adresse connue, generer le QR code avec n'importe quel
generateur gratuit, ou me redemander la diapo deja preparee. Le QR
doit pointer vers l'adresse NUE, sans ?resultat : c'est l'adresse
de vote. Verifier avant l'oral qu'il se scanne depuis le fond de
la salle.


6. LE JOUR DE L'ORAL
--------------------
- Sur l'ordinateur qui projette, ouvrir l'adresse avec ?resultat
  avant de montrer le QR code, et laisser l'onglet ouvert.
- Projeter le QR code, laisser une a deux minutes pour voter.
- Il n'y a rien a cliquer. Les biscuits se remplissent au fur et a
  mesure, et le nombre de votes s'affiche en violet sous le titre.
  Un retardataire qui vote fait simplement bouger la creme.
- Le pourcentage est ecrit sous chaque biscuit. Pour la question 1,
  plusieurs reponses etant possibles, chaque pourcentage est la part
  des votants ayant coche cette marque : le total depasse 100 %,
  c'est normal.


7. REGLES DE FONCTIONNEMENT
---------------------------
- Un vote par appareil. Le navigateur retient le vote dans sa
  memoire locale (cle mondelez_groupe1_vote). Quelqu'un qui revient
  sur la page voit directement le remerciement.
- Pour revoter pendant les essais : navigation privee, ou vider les
  donnees du site.
- Toutes les questions doivent etre remplies ; sinon un message
  rouge indique lesquelles manquent.


8. TESTER AVANT L'ORAL (A DEUX TELEPHONES)
------------------------------------------
- Telephone 1 : voter. Verifier le remerciement, et qu'aucun bouton
  de resultat n'apparait.
- Telephone 2 : voter aussi.
- Ordinateur : ouvrir l'adresse avec ?resultat. Les deux votes
  doivent apparaitre sans rien cliquer, et la creme monter. Faire
  voter un troisieme appareil et verifier que les chiffres bougent
  dans les cinq secondes.
- Verifier que le telephone 1 ne peut pas voter deux fois.
- Verifier l'affichage sur un petit ecran (moins de 420 px).
- Avant l'oral, effacer les votes d'essai : changer le nom ESPACE
  en haut du script (voir section 3), puis redeposer le fichier.


9. LES IMAGES
-------------
Les biscuits sont dessines par le navigateur a partir des
instructions contenues dans index.html. Ils ne reprennent aucune
photo de produit ni aucun logo de marque.

Une seule image vient de l'exterieur : le motif « asfalt-dark »
telecharge sur transparenttextures.com, pose sur l'anneau des
biscuits pour densifier le grain de cacao. Il pese 4 ko et ne
represente rien, c'est du grain. Le site ne precise pas sa licence
sur sa page d'accueil ; il reprend la collection Subtle Patterns,
distribuee librement, souvent citee sous licence Creative Commons
avec attribution. Le pied de page de la page mentionne donc
transparenttextures.com.

Si cette incertitude vous gene pour un travail note, la page
fonctionne tres bien sans : supprimez dans index.html le motif
t-grain et la ligne qui l'utilise,
      '<use href="#couronne" fill="url(#t-grain)"/>' +
et les biscuits retrouvent leur grain calcule, sans rien devoir a
personne.

Pour changer leur aspect, cherchez les filtres f-cacao, f-puits et
f-creme au debut du fichier. baseFrequency commande la finesse du
grain, surfaceScale le relief, lighting-color la teinte.

Pour mettre une image a vous dans l'en-tete, il faut un fichier que
vous avez le droit d'utiliser. Envoyez-le et la page sera adaptee.


10. CHOIX D'ECRITURE
--------------------
Les questions et les reponses sont en texte simple : pas d'icones,
pas d'emojis, pas d'abreviations. C'est volontaire. Au
videoprojecteur et sur les vieux telephones, une icone se lit mal
ou ne s'affiche pas du tout, alors qu'un mot reste lisible partout.
Les seules images de la page sont les biscuits des resultats.

12. LES TROIS QUESTIONS, ET CE QU'ELLES CHERCHENT
-------------------------------------------------
Q1. « Lesquelles appartiennent a Mondelez ? » Oreo, Milka, LU,
    Toblerone et Cote d'Or sont a Mondelez ; Kinder est a Ferrero,
    Lindt et Haribo sont independants. La salle va cocher au hasard
    et decouvrir l'etendue du groupe : c'est votre entree en matiere.
    VERIFIEZ CES APPARTENANCES dans votre dossier avant l'oral, les
    portefeuilles de marques changent de mains.

Q2. « Combien de salaries dans le monde ? » Un ordre de grandeur que
    personne n'a en tete, donc des reponses eparpillees, donc un
    chiffre qui marque quand vous le donnez. CONFIRMEZ LE BON CHIFFRE
    dans le rapport annuel : c'est vous qui l'annoncerez.

Q3. « Travailler pour une marque d'enfance ? » Celle-ci n'a pas de
    bonne reponse : elle divise la salle, et c'est le but. Elle vous
    donne un rebond naturel vers la partie carriere de l'expose.

Les reponses ont ete choisies pour que les biscuits ne finissent pas
tous au meme niveau. Un sondage ou tout le monde repond pareil ne
montre rien.


13. MODIFIER LA PAGE
--------------------
Le sondage compte trois questions : les marques connues, l'envie de
travailler chez Mondelez, et le critere employeur. Deux autres
questions ont existe, sur la frequence d'achat et sur la RSE ; elles
ont ete retirees pour tenir en moins d'une minute.

Le texte des questions se trouve deux fois dans index.html :
- dans le formulaire, entre les balises <fieldset> ;
- dans la liste QUESTIONS du script, qui sert aux resultats.
Si vous changez une reponse, changez-la aux deux endroits, a
l'identique, accents compris, sinon le comptage ne retrouvera pas
l'option. Si vous ajoutez une question, pensez aussi a ajouter sa
colonne dans la table : alter table votes add column q4 text;

Dans les resultats, chaque biscuit porte deux reperes :
<question>-<rang>-c pour la creme qui monte, -t pour le texte du
pourcentage. Par exemple q2-0-c est la creme du premier biscuit de
la question 2.
